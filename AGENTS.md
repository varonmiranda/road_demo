# Working notes for this repo (Base44 sandbox)

## What this project is
A static demo (no backend app, no database) served by the project's own stdlib dev server,
`serve.py`. It replays the Jan 2025 storm across **Frederick Health Hospital's own campus
surfaces** — internal drives, parking lots/aisles, the parking-garage top deck and pedestrian
walkways — inside the campus boundary from OpenStreetMap. It offers two modes: the storm replay
(`/`) and a live NWS-forecast mode (`/?mode=live` or `/index.html#live`).

The app is **campus-only by design**: it never draws or treats public city streets (those are the
city's responsibility). There are **no trucks or lane-mile metrics** anywhere in the main page.

## Layout
- Pages and Python live at the repo root: `index.html` (main), `serve.py`, `plan.py`,
  `simulate.py`, `live_plan.py`, `thermal.py`, `build_surfaces.py`, `build_basemap.py`, plus the
  legacy DC-study pages (`regression.html`, `index-v1/v2/v3-*.html`) and their build scripts.
- `data/` holds the generated assets the main page loads:
  - `surfaces.json` — the committed static campus surface inventory (geometry + static attributes).
  - `campus.js` — `window.CAMPUS = {boundary, lots}`; the boundary draws the campus outline.
  - `replay.js` / `replay.json` — the storm replay (gitignored `replay.json`, committed `replay.js`).
  - `live.js` — the live snapshot (committed; regenerated by `live_plan.py`).
  - `basemap.js`, `weather_2025-01-05_07.json`.
  - `vendor/leaflet.css`.
- `index.html` is **light-themed**: its `:root` block carries the light palette with
  `color-scheme: light`, and the map colours come from the `--risk*`, `--brine/--salt/--sand/--plow`
  and `--bm-*` tokens, so the whole page — card, legend, Details panel, Leaflet controls — follows
  those tokens.
- `index.html` draws a **real raster basemap**: Esri *World Street Map* tiles
  (`server.arcgisonline.com`, no API key). The offline vector basemap (`data/basemap.js`) is built
  into a hidden `offlineBase` layer group and swapped in automatically if four tiles fail before any
  load. The map view is clamped to the campus bounds (`CAMPUS.boundary` +5%): `frame()` zooms until
  the viewport sits inside the site, sets `minZoom`, and `maxBounds` clamps panning.

## The campus surface model
- `build_surfaces.py` reads the campus bbox straight from the OpenStreetMap API (Overpass is
  blocked in the sandbox; `api.openstreetmap.org` works) and writes `data/surfaces.json` +
  `data/campus.js`. It is idempotent (rewrites both files). Surface kinds:
  - `driveway`  — `highway=service` (not a parking aisle) inside the boundary
  - `parking_lot` — `highway=service` + `service=parking_aisle`
  - `garage_deck` — `amenity=parking` + `building=*` + `parking=multi-storey` (its roof is the deck)
  - `sidewalk` — `highway=footway/path/pedestrian`; `ramp` — `highway=steps`
  - Surface types OSM does **not** carry here (`ed_entrance`, `main_entrance`, `ramp`, `loading_dock`
    as of the last build) are written as `osm:false` placeholders so the page shows "not mapped yet"
    instead of falling back to public streets. The set is computed per run, not hard-coded.
- `thermal.surface_series` is the surface-temperature engine: air temperature nudged toward an
  equilibrium each hour, with `SURFACE_K` (asphalt vs concrete), an elevated-deck term (no ground
  coupling, stronger night sky loss) and a shaded term (less sun, less sky view). Falling snow pins
  the surface near 32 °F. All coefficients are stated assumptions, surfaced in the Details panel.
- `plan.py` turns a weather series + the inventory into per-surface hourly `temp` / `risk` (0 Low,
  1 Watch, 2 Treat soon, 3 Treat now) and `rec` (none/watch/brine/salt/sand/plow). `simulate.py`
  (replay) and `live_plan.py` (live) both call `plan.build`, so both modes share one shape:
  `{mode, hospital, boundary, hours, weather, surfaces[], risk_labels, rec_labels, assumptions}`.
  The page's `decide(t)` reads those arrays — no physics in the page.
- `build_basemap.py` (needs `osmnx`) rebuilds the offline vector basemap. `build_data.py` /
  `export_kml.py` belong to the legacy DC road study and are **not** needed for the main app.

## Rebuild commands
```bash
docker compose -f docker-compose.base44.yml exec -T web python3 build_surfaces.py  # campus inventory
docker compose -f docker-compose.base44.yml exec -T -e RSD_CACHE=/tmp/rsd_cache web python3 build_basemap.py
docker compose -f docker-compose.base44.yml exec -T web python3 simulate.py        # storm replay
docker compose -f docker-compose.base44.yml exec -T web python3 live_plan.py       # live snapshot
```
`build_basemap.py` needs `osmnx` (not in the image — `pip install osmnx scikit-learn` into the
running container, and keep the large graph cache out of git with `RSD_CACHE`). `build_surfaces.py`,
`simulate.py` and `live_plan.py` need only `requests`/stdlib.

## Run it here
```bash
docker compose -f docker-compose.base44.yml up -d --build   # http://localhost:3000
docker compose -f docker-compose.base44.yml logs -f web
```
- `serve.py` reads `PORT` (compose sets 3000) and binds 0.0.0.0.
- `Dockerfile.base44` installs dependencies only; the source is bind-mounted, so page/JS/data
  edits need **no rebuild**.
- **No live reloader**: `serve.py` is a plain `http.server`. HTML/JS/data edits are served fresh on
  the next request (`Cache-Control: no-store`), but after editing `serve.py`, `plan.py`,
  `simulate.py`, `live_plan.py` or `thermal.py` restart the service:
  `docker compose -f docker-compose.base44.yml restart web`.

## First boot / data that is not in the repo
- `data/replay.json` is **not** committed (gitignored), but the compose command generates it once
  with `python3 simulate.py`, which is deterministic and needs no network (it uses the committed
  `data/surfaces.json` and `data/weather_2025-01-05_07.json`). Afterwards the file sits in the
  bind-mounted repo.
- `data/replay.js` and `data/live.js` are generated artifacts committed as snapshots.
  `simulate.py` rewrites `replay.js`; `live_plan.py` (or the page's **Refresh forecast** button,
  `POST /api/refresh?drill=0`) rewrites `live.js`. Regenerating them leaves the tree dirty — restore
  with `git checkout -- data/replay.js data/live.js` if a clean tree matters.

## Credentials
None. Live mode calls `api.weather.gov`, which needs no API key (only internet access and a
descriptive User-Agent, which `live_plan.py` sets). `/run/base44/app.env` is not referenced by
compose. The legacy Earth Engine scripts (`gee_features.py`, `gee_citywide_sample.py`) are part of
the DC study and are not needed to run the demo.

## Sandbox / preview notes
- No host or origin allowlists in the code, so no sandbox-only config overrides are needed and
  nothing is gated on `BASE44_PREVIEW_MODE`.
- The page treats any hostname that is not `localhost`/`127.0.0.1` as "static" (`index.html`, the
  `STATIC` constant): it labels live mode "Snapshot of the …" and never renders the **Refresh
  forecast** / **Drill −25 °F** controls. Sandbox previews come through the proxy host, so those two
  controls are absent in the preview. The endpoint works regardless — verify with
  `curl -s -X POST 'http://localhost:3000/api/refresh?drill=0'` (it rewrites `data/live.js`; run
  `git checkout -- data/live.js` afterwards to keep the tree clean).
- Leaflet and the Google fonts load from CDNs, so the browser needs internet access.

## How to verify
```bash
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:3000/                  # 200
curl -s http://localhost:3000/ | grep -c 'Hospital Salting Advisor'              # 2
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:3000/data/replay.js    # 200
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:3000/data/surfaces.json # 200
docker compose -f docker-compose.base44.yml ps                                   # web = healthy
```
In the preview: the card reads "Treat now / Treat …" during the storm, surfaces turn amber/red at
the storm peak, the legend matches, the Details panel lists the ordered campus checklist and the
per-surface table, and no console errors appear. Live mode (needs internet, ~15 s):
`curl -s -X POST 'http://localhost:3000/api/refresh?drill=0'` → `{"ok": true, "summary": "NWS …"}`.
